# 热点取材

自动发文先获取固定数据源，再让 Codex 按主题选题和核实，避免只做泛化搜索。

- `weibo`：60s `/v2/weibo` 微博热榜。
- `rednote`：60s `/v2/rednote` 小红书热榜。
- `hot_topics`：两个热榜。
- `international`：BBC 娱乐、Guardian 文化 RSS（最近 48 小时）。
- `mixed`：两个热榜及上述 RSS。
- `web`：原有 Codex 全网新闻检索。

复用 [60s-skills/hot-topics](https://github.com/vikiboss/60s-skills/tree/main/skills/hot-topics) 的公开 API，以及 [news-aggregator-skill](https://github.com/cclank/news-aggregator-skill) 的 RSS 取材方法。后台直接读取数据，不额外安装其全量运行环境；本机和 Docker 使用同一套后端实现。60s 为第三方聚合服务，榜单保留实际来源，不标成平台官方 API。

后台接口 `news_sources` 接受 `source`，用于预览，不生成或发布帖子。响应包含 `items`、各平台 `counts`、`retrieved_at` 和 `errors`；每个成功的完整批次缓存五分钟。超时、非成功 HTTP、结构错误会列入失败来源；其余可用来源仍可使用。全部来源为空时不调用 Codex。请求只访问固定 HTTPS 地址，无需平台账号、Cookie 或 API Key，不启动浏览器。

热榜只有标题、热度和搜索链接，`published_at` 保留为 null；不能用取榜时间冒充原文时间。RSS 保留媒体链接、摘要和原始发布时间；模型不得改写该时间。热榜仅用于选题，生成前还需公开原帖或可信报道核实；取不到足够事实则本轮跳过。任务 input 的 `news_feed` 和“新闻取材”日志保留当时数据和失败来源。

计划 `include_source_link: false` 时，最终英文/中文正文不能含 URL；核实后的来源仍写入 `input.source.url`。旧计划缺少该字段时保留原来的附链接行为。当前只支持文字发布，未添加自动抓取或上传图片、视频。

## 通知回复间隔

通知回复计划支持 `interval_seconds: 25`，保留 `interval_minutes` 兼容旧计划。秒级间隔适用于 `reply_notifications` 和 `auto_reply`；前端在这两类任务下提供“每25秒”。保存设置保持暂停，不会因此启动计划。调度、恢复计划和每次确认发送后的间隔使用同一个时间计算，生成或发送慢时顺延，不并行追赶积压。通知请求返回 HTTP 429 时使用现有“操作过于频繁”暂停机制，不继续自动重试。这个设置不启用 For You 的陌生帖批量评论。

## 分批热点与逐条发文

微博、小红书和 RSS 来源先采集一批并持久化到 SQLite。侧边栏独立的“热点列表”显示来源标签、发布时间、采集时间、X 发布状态、当前批次进度、分页历史、跳过原因和已发布链接。列表按新闻时间倒序，热榜未提供发布时间时按采集时间排序；发送回执不确定时显示待核对。每个发文周期只分配一条候选给一个任务，核实、生成、发送完成后，下一周期再取下一条。当前批次全部处理完（含失败、重复、无法核实或过期）才拉取新批次；已消费的来源链接或热榜标题按账号去重。超过48小时的候选会跳过，失败条目不会自动重发。更换计划来源或主题会使用新批次，原记录保留。全网搜索来源仍按次定向搜索，没有固定榜单批次。

模型每次仅收到当前候选，RSS 摘要移除 HTML 并截到800字符，近期排除项最多20条；完整发布历史仍由后台校验去重。不再向模型重复传入整批热榜。实际 token 用量仍包含联网核实与模型输出，以每条任务的用量记录为准。

热点列表的渠道与执行状态筛选在后台先过滤、再分页，支持组合筛选，切换条件回到第一页；当前批次整体进度不随列表筛选改变。历史已发布记录同样参与“已发 X”筛选，发送后未确认回执的记录归入“待核对”。
