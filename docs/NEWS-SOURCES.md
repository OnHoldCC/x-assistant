# 热点取材

自动发文先获取固定数据源，再让 Codex 按主题选题和核实，避免只做泛化搜索。

- `weibo`：60s `/v2/weibo` 微博热榜。
- `rednote`：60s `/v2/rednote` 小红书热榜。
- `hot_topics`：两个热榜。
- `international`：BBC 娱乐、Guardian 文化、Variety、Deadline RSS（最近 48 小时）。
- `mixed`：两个热榜及上述 RSS。
- `web`：原有 Codex 全网新闻检索。

复用 [60s-skills/hot-topics](https://github.com/vikiboss/60s-skills/tree/main/skills/hot-topics) 的公开 API，以及 [news-aggregator-skill](https://github.com/cclank/news-aggregator-skill) 的 RSS 取材方法。后台直接读取数据，不额外安装其全量运行环境；本机和 Docker 使用同一套后端实现。60s 为第三方聚合服务，榜单保留实际来源，不标成平台官方 API。

后台接口 `news_sources` 接受 `source`，用于预览，不生成或发布帖子。响应包含 `items`、各平台 `counts`、`retrieved_at` 和 `errors`；每个成功的完整快照最多缓存60秒。超时、非成功 HTTP、结构错误会列入失败来源；其余可用来源仍可使用。全部来源为空时不调用 Codex。请求只访问固定 HTTPS 地址，无需平台账号、Cookie 或 API Key，不启动浏览器。

热榜只有标题、热度和搜索链接，`published_at` 保留为 null；不能用取榜时间冒充原文时间。RSS 保留媒体链接、摘要和原始发布时间；模型不得改写该时间。热榜仅用于选题，生成前还需公开原帖或可信报道核实；取不到足够事实则本轮跳过。任务 input 的 `news_feed` 和“新闻取材”日志保留当时数据和失败来源。

计划 `include_source_link: false` 时，最终英文/中文正文不能含 URL；核实后的来源仍写入 `input.source.url`。旧计划缺少该字段时保留原来的附链接行为。当前只支持文字发布，未添加自动抓取或上传图片、视频。

## 通知回复间隔

通知回复计划支持 `interval_seconds: 25`，保留 `interval_minutes` 兼容旧计划。秒级间隔适用于 `reply_notifications` 和 `auto_reply`；前端在这两类任务下提供“每25秒”。保存设置保持暂停，不会因此启动计划。调度、恢复计划和每次确认发送后的间隔使用同一个时间计算，生成或发送慢时顺延，不并行追赶积压。通知请求返回 HTTP 429 时使用现有“操作过于频繁”暂停机制，不继续自动重试。这个设置不启用 For You 的陌生帖批量评论。

## 最新热点与随机选题

自动发文每轮重新读取最新热榜和 RSS 快照，不再等待旧批次耗尽。候选列表随机打散后交给 AI，AI 按计划主题筛选并沿随机顺序核实，最多选一条发布；不适合的候选可以换下一条。未选中的候选不绑定发文任务。模型返回的 news.title 必须保留所选候选的原始标题，RSS 还必须保留原链接与发布时间；热榜题目需要核实真实原帖或报道。候选均不合适时明确记录跳过原因，不把采集完成当作发布成功。

执行间隔可设为每1分钟，即每60秒启动新一轮。生成或浏览器执行慢时顺延，同账号不会并行补发；已确认发送仍保留最小发送间隔。新闻任务成功后不额外推迟下一轮取材。全网搜索来源仍按次定向搜索，没有固定榜单快照。

侧边栏“热点列表”保留已处理候选的执行状态、X 回执和分页历史；新快照覆盖尚未处理候选的内容和采集时间，未出现在最新快照中的旧候选标为已替换。已消费的来源链接或热榜标题按账号去重，失败或结果不确定的发送不会自动重发。来源部分失败仍保留可用渠道，全部为空不调用模型。

Token 包括候选列表、联网核实与模型输出，以每条任务的用量记录为准。模型近期排除项最多20条，完整发布历史仍由后台校验去重。

## 避免重复空稿与用量空转

每轮最多交给 AI 8 条随机候选。存在带摘要的媒体 RSS 报道时优先从这些报道选题，直接根据抓取到的原始标题、摘要和发布时间生成短帖，不重复联网搜索；后台逐字核对原始摘要、链接和时间，并继续校验数字、来源和去重。默认关闭 `allow_news_search`：只有热榜标题、原文摘要为空时，本轮不调用模型；全网搜索来源也必须明确开启此选项才能生成。用户可在新闻计划中开启「允许联网核实无摘要的热点」，这会额外消耗 Token。新建计划默认使用 RSS 来源。

模型跳过必须返回 skip_reason，具体理由显示在任务结果并保留原始跳过输出。模型已否决的候选不会仅因时间、热度、排名或发布时间变化再次调用模型；标题、摘要或计划选题变化后才重新参与评估。每60秒仍正常抓取来源，没有新增或可重试候选时直接跳过，不调用模型。


### 省 Token 默认策略

- 每60秒仍可抓取最新候选；取材频率不等于模型调用频率。
- 模型已否决且标题、摘要及计划选题未变化的候选不再按时间自动重试。热度、榜单名次、采集时间和发布时间变化不会单独触发重新调用；标题、摘要或选题改变时可重新评估。旧版否决缓存沿用原批次的选题键。
- 无摘要或没有新增可用候选时明确记录「未调用模型」，不创建虚假的模型调用用量；缺失的真实模型用量仍保留为未知。
- 原文验证、去重、语言和发送回执校验保留；低消耗不代表强行发布不符合选题的内容。
