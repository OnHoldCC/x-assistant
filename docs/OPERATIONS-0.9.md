# OnHold 0.9 运营口径与交付范围

面向 X 内容创作者和独立运营者。首页回答：账号表现怎样、哪些内容值得继续、距离创作者变现还差什么。模型、连接参数是偏好设置，不是主导航。

| 目标 | 主要指标 | 口径 |
| --- | --- | --- |
| 触达 | 曝光量、单帖浏览、发帖数 | 官方全量与本地已采帖子分别展示；浏览不是独立人数 |
| 内容效果 | 总互动、官方互动率、评论、转发、收藏、分享 | 官方互动率与自定义加权参考值分开 |
| 账号增长 | 新增关注、取消关注、净增关注 | 使用同周期数据；不把同周期净增直接归因给某条帖子 |
| 主页吸引力 | 主页访问、访问/曝光比 | 事件比率，不是独立用户转化率 |
| 创作者资格 | 认证粉丝、认证主页曝光、对应门槛与时间窗 | 从本人创作者页面读取，不以总曝光替代 |
| 收益 | 可用的近30天合格曝光与本人历史结算单价 | 手动校准的情景估算，不冒充官方结算；不具备依据则不生成金额 |

依据：[X 分析说明](https://business.x.com/help/tweet-activity-dashboard)、[Original Content Rewards](https://help.x.com/en/using-x/original-content-rewards)。规则于2026-10-28核对，产品仍以各账号当前官方页面为准。

官方曲线读取 CSV 中的实际日期和数值。多指标同图采用各自峰值100的相对刻度，悬停显示实际值；选择单项后使用原始刻度。日/周/月汇总重新计算互动率；缺失值不补零。预设周期跟随页面实际提供的选项。每5分钟刷新主页、最近7天官方曲线和创作者进度；手动采集更新全部可用周期，浏览器离线或退出登录时暂停。不同累计周期不能直接拼成逐日曲线。

收藏保存到当前账号的 OnHold 资料库，可添加、编辑标签。不会自动操作 X 的收藏状态。用户可保存其他作者的公开帖子，而不会混入本人账号的帖子统计。新建自动化任务默认暂停；取消关注默认只处理由自动化关注、到期且未回关的人，也支持明确的手动名单。

关注、取消关注通过正常 X 控件执行，逐个确认操作结果。出现关注限制、429、账号验证或不确定结果即停止；限制状态保存到后台和插件会话，暂停该账号后续写操作。只有用户确认解除后才能恢复。验证码和验证步骤不自动处理。每个已确认的动作立即留存，连接中断也不抹掉已完成记录。

长期记忆包括账号偏好、已采历史、收藏和用户标记采用的复盘。模型只获取发送前预览的相关摘录，不自动发送全部历史，也不接触 API Key。支持本机 Codex CLI 和兼容 Responses / Chat Completions 的 API；前者独立只读执行，后者使用本机系统凭据库。调用依据：[Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)。模型建议需要后续验证，采用记录不等于证明建议有效。

作者页为 X、Telegram、GitHub 地址及默认折叠的版本记录。全局顶部展示沿用 OnHold 字体的金色文字费用标签，CSS 白光扫过；减少动态效果时停用扫光。

系统日志通过桌面事件实时更新，保留最近10000条，界面显示最近1000条并提供轮询补偿。不记录密钥、登录凭证、模型完整输入或帖子正文。

Mac 图标改为全画幅背景 ICNS，避免透明边距叠加。仍需在目标 macOS Dock 验证实际显示。Windows 凭据存储实现随源码提供，安装和真实账号自动化需分别实机验证。API Key 未提供时不进行付费服务调用测试。

## 一键改写与定时发布

X 帖子旁的“详情”已替换为“一键改写”。点击只提交当前原帖，不发送收藏库或运营记忆；桌面端使用已配置并登录的 Codex CLI 按固定提示词润色，保留事实、数字、链接、账号和话题。提示词维护于 `app/src-tauri/src/models.rs` 的 `REWRITE_INSTRUCTIONS`。数字、链接、账号和话题变化会让任务失败。

同一工具栏提供“生成同类文章”：参考当前完整原帖的主题、体裁、受众、语气和篇幅，重新组织开头、论述与结尾，保留原文事实与受保护字段，不编造经历和案例。使用独立的 `SIMILAR_ARTICLE_INSTRUCTIONS`；原样返回原文会失败，可手动重试。同一原帖的改写和同类文章分别去重，旧任务继续按改写处理，无需数据库迁移。

在“任务记录”可展开原文与生成正文、点击“复制正文”。生成和复制不会自动安排发布，默认不发帖；只有手动设置时间才进入已有定时发布流程。真实模型的表达与事实归属仍需对照核对。

在后台“任务记录”（手机底栏“任务”）通过表格查看执行列表：等待改写 → 改写中 → 待设置时间 → 等待发布 → 执行中 → 已完成 / 失败。工具栏提供新增、搜索和状态筛选；查看或编辑行内任务时，在抽屉核对原文、正文与发布时间。列表每两秒更新，空数据保留表头。未安排时间的任务不会发布。错过计划时间时等待桌面端与同一账号的浏览器重新在线，不在离线状态伪造成功。

自动化计划也使用表格，支持新增、查看、编辑、启停与删除；保存修改后保持暂停，等待核对再启用。任务记录允许编辑等待中的采集类型和已生成正文，正文仍必须保留原帖的数字、链接、账号与话题。删除前在抽屉确认，运行中的任务不能删除；未执行项会取消，已发生的操作不会撤销，历史记录继续保留以防重复发帖。

执行时创建独立的 X 首页标签页，通过 CDP 鼠标事件聚焦输入框，以原生文本输入写入正文，再点击发送。不会覆盖已有草稿；来源账号、实际输入内容、发送按钮和后台一次性发送标记都通过校验后才点击。只有匹配正文请求和当前账号的成功发布回执才记为完成。失败标签页保留用于检查；已点击发送但回执丢失的任务不提供自动重试，以免重复发帖。

需要运行新版桌面端并重载 1.5.0 版助手；独立 Rust 后台没有 Codex CLI 改写执行器。任务、计划时间和发送标记使用已有数据库 jobs 表保存，不更改数据库版本。X 的字数或账号权限仍以页面实际限制为准，按钮不可用时保留草稿并记录失败。

关系名单（配套助手 1.5.1）：自动化页提供已关注、粉丝、待回关、未回关四种筛选，以及搜索、每页 50 人和勾选创建暂停任务。同步按需执行，每批最多读取 3 页，未完成可沿用游标继续；仅在明确结束完整同步后，才将未出现的人标为不在名单中。缺失关系标记保留未知，不计入未回关。自动回关从已同步且确认未关注的粉丝中选择目标；取消关注的默认范围仍限于本系统关注记录。执行前仍检查 X 当前关系。

发帖与回复输入框提供聚焦和一键翻译入口，空正文时翻译按钮禁用；翻译先预览，再手动应用，可撤销，不触发发帖。自动发布必须验证实际正文输入框已取得焦点，失败时停止，不向其他控件输入。翻译需要本机模型服务运行；这些界面与夹具检查不代替真实 X 关系接口及真实发布验收。

### 发同款与执行进度

帖子工具的“发同款”只发送该原帖的作者、来源 URL/ID 和正文给 Codex，不打包账号运营记忆。任务 mode 为 `replicate`，与 `similar` 同类草稿分开：Codex 使用 `lib/replicate-schema.json` 的 JSON Schema 返回 `schema_version:1`、`analysis:{topic,structure,tone,key_points}`、`text`；后台严格校验字段、原文数字/链接/@账号/#话题、重复正文，成功后自动进入发送队列。来源元数据不能擅自加进正文，正文编号也不能引入新数字。Codex 自己不调用发帖工具。

只有用户明确点击“发同款”或任务表单的“创建并自动发布”才选用此模式；“改写原帖”“生成同类文章”仍默认保持草稿，需手动排期。真正发送由已连接插件核验当前账号、输入框焦点和未发送草稿，单次点击发送，并以匹配当前账号的 X 网络回执 URL 标记成功；发送结果不确定不重试。格式错误、事实变更和缺少分析会停止在生成阶段。

任务列表和自动化列表显示执行进度。Codex 生成期间显示不定进度，不按耗时伪造百分比；发布按生成/校验、等待发送、发送确认、结果回执展示阶段。回关/取消关注按本轮真实目标数和后台已记录的成功、跳过回执计数，失败保留部分完成，达到每轮时限的部分结束不冒充全部完成。定时计划通过 `last_job` 返回本轮或最近一轮执行详情，独立于下次调度时间。

### For You 自动评论（插件 1.5.6）

在「自动化」新增 **自动评论（For You）**，保存后保持暂停；启用后按配置间隔（最短 1 分钟）读取 For You，每轮 1–20 条。每条有效原帖创建一个独立回复任务：原帖内容 → Codex CLI 固定 JSON（`schema_version`、`text`）→ 校验 → 原帖回复框 → X 回执。评论不依赖决策评分，低分帖子也会处理。需要已登录的 Codex CLI；Docker 安装需启用 `agent` 配置并完成登录，浏览器插件需保持连接。

采集后在插件会话中保存当前页的固定链接和正文，按每轮上限逐条处理完该页的有效帖子，再刷新读取下一页。当前页剩余帖子不会因每轮重新打开首页而被覆盖。会话缓存按账号和来源隔离；浏览器重启后重新采集，服务端历史去重仍保留。成功发送后，下次执行时间至少间隔配置的分钟数，避免任务积压后连续追发。可设置自动停止时间，到时暂停并阻止新的生成、领取和发送。

采集明确选中 For You，不读取 Following；跳过自己、广告、无正文、展开前不完整的帖子。原帖语言和页面翻译状态不影响候选筛选，内容语言只控制生成回复的语言。同一账号按原帖 ID 去重，包括失败、删除和发送结果不确定的历史任务。暂停阻止新采集、下一条生成及发送前操作；已经发出的请求无法撤回。每轮进度根据子任务的成功/失败数量展示，每条任务保留原帖、生成正文、错误和回复链接。请求正文与原帖 ID 在网络发出前核对，回执还需匹配当前账号及被回复原帖。结果不确定不自动重发。

验证：Rust 任务测试覆盖归属、整批回滚、数量上限、去重、暂停、停止时间、发送间隔和原帖回执；浏览器隔离测试覆盖 For You 切换/过滤、当前页消费后刷新、评论不调用评分、原生聚焦输入、发送前拦截错误目标、草稿保留和账号切换。实际调用已登录 Codex，完成两条原帖的「采集 → 分别建任务 → 生成 → 浏览器发送 → 回执 → 数据库完成」全链路测试（约 29 秒）。这次全链路测试中的 X 请求均由隔离测试页拦截，没有公开发送。

真实 X 验证补充（2026-10-29）：已使用 @onholdcc 实际采集 For You、调用 Codex 并发送一条回复，获得匹配的真实回执并打开回复页面核对成功。实测发现并修正 `/compose/post` 回复弹窗路由兼容问题。证据见 [真实回复记录](LIVE-REPLY-2026-10-29.md)。这是单次真实验证，持续运行状态需以当前插件版本、连接和任务回执为准。

### 五类自动化与新闻发文（助手 1.5.7）

自动化列表区分自动发文、自动评论（For You）、自动回复（通知）、自动回关和一键取消关注，各自保存配置并独立启用。自动回关选择「通知中的新关注者」时，列表显示「自动回关（通知）」；按计划读取新关注通知，确认关系后回关，不调用模型。通知回复与通知回关需分别创建计划。

自动发文已改为：填写新闻主题 → Codex 联网搜索 → 核对最近48小时新闻及来源 → 整理中文 X 短帖 → 格式、日期和去重校验 → 发布任务。去掉评分门槛和评分模型依赖，插件不再显示内容评分按钮，Docker 不再部署 Laya 评分服务；翻译仍为选配。已有新闻任务的URL和标题会排除，当前账号已有来源或相同正文时不重复发布。搜索失败、没有可核实的新新闻、过期或未来日期、缺来源链接时均不发布。正文、新闻来源、发布时间、用量和耗时保留在任务详情。

新闻检索只启用 Codex 联网搜索，命令与文件操作保持禁用；要求JSON执行记录中出现实际完成的搜索事件，防止把模型记忆冒充实时搜索。普通改写、发同款和评论保持联网工具关闭。该检索路径需要已登录的 Codex CLI；普通文章API配置不提供新闻搜索。

X 官方自动化规则明确禁止网站脚本操作和未经请求的批量自动回复，AI回复机器人还需事先书面批准。模拟输入和点击不能保证账号安全；人工辅助写作与定时程序自动发送应区分。使用者应了解发布方式及行为风险，不能将测试通过或低频操作宣传为免封号。来源：[X 自动化规则](https://help.x.com/en/rules-and-policies/x-automation)。

### 自动化评论、通知回复与用量记录（助手 1.5.5）

- **自动化评论（For You）**：读取推荐流，保留原帖 ID、链接及正文，Codex 生成后打开原帖发表评论。
- **自动化回复（通知）**：打开小铃铛通知，读取页面自身的 NotificationsTimeline 响应，只处理明确 `in_reply_to_user_id_str` 指向当前账号且有原帖 ID 的消息；跳过点赞、转发、单纯提及和自己的消息。回复目标为对方这条消息的固定链接。2026-10-29 已只读确认真实通知接口及上述回复归属字段；隔离浏览器测试已覆盖通知读取、筛选及任务提交，本次没有新增公开发送通知回复。

两类任务共享“账号 + 目标帖子 ID”的本机去重记录。成功、发送结果不确定、历史失败及软删除任务都会阻止重复建任务；生成或发送前失败可手动重试原任务，已尝试发送的任务不能自动重发。去重依据本机任务历史，不代表已同步账号此前所有手工回复。

每条任务详情现在显示：原帖、回复正文、回复链接、结果、总耗时（含排队和重试等待）、生成耗时、发送耗时、模型调用次数、输入/输出 token、缓存输入及逐次调用记录。重新生成会追加一次记录，重试发送复用正文，不重复记为模型调用。缓存输入已包含在输入 token 中，总数按输入加输出计算；缺失用量显示“未记录/未知”，不会写成零或用字符数估算。先前公开发送的那条任务没有保留模型 usage，仍无法补回 token。

Codex 本机、桌面及 Docker 路径统一读取 `--json` 输出的 `turn.completed.usage`，正文仍来自独立的最终消息文件，避免把模型正文中的 `usage` 当成计量数据。参考 [OpenAI 非交互模式文档](https://learn.chatgpt.com/docs/non-interactive-mode)。真实 CLI 独立验证成功读取：输入 14589、输出 51、总计 14640 token，生成约 15.77 秒；这是合成文本的计量验证，与此前那条公开评论的用量不同。
